# 理解 PyTorch 的基础框架

PyTorch 是一个 Python 库。它负责把数放进张量、按层算出分数、算出损失、再改 `W` 和 `b`。这些步骤本身是人工神经网络，换一个库，步骤的含义还在。

所以框架分成两层。左边是人工神经网络里的概念，右边是 PyTorch 用来装它的对象。读 `examples/mnist-digits/train.py` 时，每一行都能落进其中一格。

细读仍放在原来的笔记里：网络流水线见 [00-neural-network-framework.md](00-neural-network-framework.md)，张量的下标见 [pytorch-tensor.md](pytorch-tensor.md)，`train.py` 里的调用见 [pytorch.md](pytorch.md)。对着 `train.py` 看 Python 写法和每一批张量的形状，见 [语法和张量.md](../../examples/mnist-digits/语法和张量.md)。

<a id="map"></a>

## 总图

```text
一个样本 = 特征 + 标签
    小明 [8, 2, 6]，标签「喜欢」
    一张数字图 784 个亮度，标签 0～9
        │
        │  参数 W、b 对所有样本是同一套
        ▼
前向：特征 → 分数
    线性层 y = x W + b
    ReLU：负数改成 0
    再一层线性层，得到分数
        │
        ▼
分数 → 百分比 → 损失（一个数）
    小明的分数 [3.2, −0.7]
    百分比 [0.980, 0.020]
    损失 −ln(0.980) ≈ 0.020
        │
        ▼
梯度：每个参数旁边一张同形状的表
    「这个数加大一点，损失加大多少」
        │
        ▼
更新：朝损失变小的方向改 W、b
```

一批样本共用一次更新。训练集走完一遍叫做一轮。测试集只做前向，用来看没见过的样本，不改参数。

## 概念对照

| 概念 | 人工神经网络里它是什么 | 奶茶或读数字里的数 | PyTorch 里装在哪里 |
| --- | --- | --- | --- |
| 特征 | 描述一个样本的一排数 | 甜、冰、茶；或 784 个亮度 | `Tensor`，最后一轴是特征 |
| 标签 | 这一样本的正确答案 | 喜欢；或数字 7 | `int64` 张量，内容是类别编号 |
| 参数 | 训练要改的 `W`、`b` | 四组：`W1` `b1` `W2` `b2` | `nn.Linear` 的 `weight`、`bias` |
| 前向 | 用当前参数把特征算成分数 | `[8,2,6] → [6,8] → [3.2,−0.7]` | `model(x)`，也就是 `forward` |
| 线性层 | 加权和再加底分 | 清爽 `= 1×冰 + 0.5×茶 + 1` | `nn.Linear` |
| ReLU | 负数改成 0 再送出 | 热浓茶的清爽 −4 变成 0 | `torch.relu` |
| 隐藏层 | 特征和图上的类别之间的检测 | 清爽、甜腻；或 128 个检测 | 第一层 `Linear` 加 ReLU 的输出 |
| 分数 | 每一类一个数，越大越像 | `[3.2, −0.7]`；或 10 个数字的分数 | `forward` 的返回值 |
| 百分比 | 分数经过 Softmax，加总为 1 | `[0.980, 0.020]` | 损失内部；打印时用 `softmax` |
| 损失 | 正确那一类有多不准，一个数 | 0.020 | `nn.CrossEntropyLoss` |
| 梯度 | 每个参数该往哪边改 | 喜欢的底分梯度 −0.01984 | `backward()` 填到 `.grad` |
| 更新 | 按梯度改参数 | SGD 把 `w=1` 改成 1.12 | `optimizer.step()` |
| 一批 | 若干样本一起算一次损失、改一次参数 | 64 张图 | `DataLoader` 每次给出的张量 |
| 一轮 | 训练集每个样本都看过一遍 | 60000 张，938 批 | `for epoch` 里的一次 `train_one_epoch` |
| 测试 | 用没参与改参数的样本看效果 | 10000 张，读对约 94.5% | `evaluate`，包在 `no_grad` 里 |

<a id="sample"></a>

## 样本、特征和标签

一个样本是「看到的东西」加上「应该回答的类别」。

奶茶里，看到的东西是三个特征：甜、冰、茶。小明是 `[8, 2, 6]`。应该回答的类别是喜欢。热浓茶是 `[0, −6, 2]`，类别是不喜欢。

读数字时，看到的东西是 28×28 的亮度，拉直后 784 个特征。应该回答的类别是 0 到 9 里的一个整数。

特征会换，参数不换。换一杯饮料或换一张图，变的是输入；`W` 和 `b` 仍是上一批留下的那一套。

标签在笔记里可以写成两格：喜欢是 `[1, 0]`，表示正确的百分比落在第 0 格。PyTorch 的 `CrossEntropyLoss` 直接收这个格子的编号，所以喜欢写成整数 `0`，不喜欢写成整数 `1`。一张数字图的标签就是 `7` 这样的一个整数。两种写法指的是同一格。

<a id="param"></a>

## 参数

参数是训练要改的数。这个两层网络有四组：

```text
W1  把甜、冰、茶收成清爽、甜腻     笔记里的形状 3×2
b1  这一层的底分                   [1, 0]
W2  把清爽、甜腻收成喜欢、不喜欢   笔记里的形状 2×2
b2  这一层的底分                   [0, 0.5]
```

读数字把宽度放大：`W1` 是 784×128，`b1` 长度 128，`W2` 是 128×10，`b2` 长度 10。参数个数是 `128×784 + 128 + 10×128 + 10 = 101770`。另一份常见小网络把这四个宽度写成 `n_in`、`n_h`、`n_out` 和 `batch_size`，见 [层宽度](pytorch-layer-sizes.md)。

输入 `x` 不是参数。损失也不是参数。梯度不是参数，它是「这一步建议怎么改参数」的一张表，改完可以清掉。

<a id="forward"></a>

## 前向

前向是用当前参数，把一个样本的特征算成各类的分数。小明：

```text
清爽 = 0×8 + 1×2 + 0.5×6 + 1 = 6
甜腻 = 1×8                     = 8
ReLU 之后仍是 [6, 8]

喜欢   = 0.4×6 + 0.1×8 + 0   = 3.2
不喜欢 = −0.2×6 + 0×8 + 0.5 = −0.7
```

这四行就是前向。PyTorch 里写在 `forward` 里，调用时写成 `scores = model(images)`。

<a id="linear"></a>

## 线性层

线性层做的是加权和，再加底分：`y = x W + b`。

上面清爽那一行，`0, 1, 0.5` 是 `W` 的一行，`+1` 是底分。冰从 2 增加到 3，清爽就从 6 增加到 7，增加量和甜、茶是多少没有关系。这种「每一项单独加分」就是线性。

PyTorch 的 `nn.Linear(3, 2)` 把笔记里 3×2 的 `W` 存成 `weight`，形状 `(2, 3)`，计算时先转置再乘，乘积相同。最后一轴被当成特征。`(2, 3)` 的两杯进去，出来仍是两行，形状 `(2, 2)`。细读在 [线性层](03-linear-relu-embedding.md) 和 [张量](pytorch-tensor.md)。

<a id="relu"></a>

## ReLU

ReLU 的全称是 Rectified Linear Unit。它放在两层线性层中间，规则是：负数改成 0，正数原样送出。

热浓茶的清爽算出来是 −4。ReLU 之后这一格是 0，第二层的「喜欢」收到的清爽就是 0。甜腻也是 0，喜欢的底分是 0，所以喜欢的分数是 0。

这一格已经是 0 以后，冰再低，送出去的清爽仍是 0，喜欢的分数不再跟着降。细读在 [ReLU](03-linear-relu-embedding.md)。

<a id="hidden"></a>

## 隐藏层

清爽和甜腻是隐藏层：人看的是甜、冰、茶，答案是喜欢或不喜欢，中间这些格不直接当答案。

一层线性层是一次加权和，分界是平的。有些规则一层加权和做不到。四杯饮料里，只甜或只冰算喜欢，又甜又冰、以及都不甜不冰算不喜欢。甜和冰的权重若都是正的，又甜又冰的那一杯分数最高，和这条规则相反。中间加上 ReLU 以后，可以先做两个检测：偏冰、偏甜。两个检测再相加，四杯的分数就能是 2、2、0、0。

「清爽」「甜腻」是为了手算起的名字。读数字的 128 个检测没有事先起名。训练只看见标签，改完权重之后，人可以再去看某一格像不像一小段笔画。隐藏层为什么需要，写在 [框架笔记的这一节](00-neural-network-framework.md#why-hidden)。

<a id="softmax"></a>

## 分数和百分比

前向结束时得到的是分数，一类一个。小明是 `[3.2, −0.7]`。分数可以是负数，加起来也不是 1。

Softmax 把分数变成百分比：先对每个分数取指数，再除以这些指数的和。

```text
e^3.2 ≈ 24.5325
e^(−0.7) ≈ 0.4966
和 ≈ 25.0291

喜欢   24.5325 / 25.0291 ≈ 0.980160
不喜欢  0.4966 / 25.0291 ≈ 0.019840
```

两个百分比都大于 0，加起来是 1。分数最大的那一格，百分比也最大，所以读类别时可以直接取分数最大的下标。百分比的算法写在 [Softmax](02-softmax.md)。

<a id="loss"></a>

## 损失

损失把「算成的百分比」和「标签」收成一个数。这个数越小，正确那一类的百分比越接近 1。

小明的标签在第 0 格，这一格的百分比是 0.980160。损失是

```text
−ln(0.980160) ≈ 0.020040
```

热浓茶的分数是 `[0, 0.5]`，标签是不喜欢。不喜欢的百分比约 0.622，损失约 0.474。两杯一起算时，`CrossEntropyLoss` 默认取平均，约 0.247。

读数字的一批有 64 张，损失是这 64 张的平均。训练全程盯着的就是这一个数：它变小，表示正确那一类的百分比整体在变大。

<a id="grad"></a>

## 梯度

梯度回答：某一个参数单独加大一点点，损失会加大多少。

每个参数旁边都有一张梯度，形状和这个参数相同。小明这一杯、标签是喜欢时，第二层底分 `b2 = [0, 0.5]` 的梯度是

```text
[−0.019840, 0.019840]
```

手算就是「当前百分比 − 这一格的答案」：

```text
喜欢：  0.980160 − 1 = −0.019840
不喜欢：0.019840 − 0 =  0.019840
```

喜欢这一格的梯度是负的：把喜欢的底分加大，损失下降。不喜欢这一格的梯度是正的：把不喜欢的底分加大，损失上升。更新时要损失变小，所以朝梯度的反方向改。

`W` 的梯度同样是一张和 `W` 同形状的表。它由损失一路乘回输入。清爽还大于 0 时，ReLU 把梯度原样送回第一层。清爽已经是负数、被 ReLU 改成 0 的那一杯，这一路送回去的梯度是 0。

<a id="update"></a>

## 更新

拿到梯度之后，真正改参数的是更新。用一个数看 SGD。设 `w = 1`，分数 `= 3w`，损失 `= (分数 − 5)²`。

```text
分数 = 3
损失 = 4
梯度 = −12
学习率 0.01：  w ← 1 − 0.01×(−12) = 1.12
```

分数从 3 变成 3.36，靠近目标 5。

读数字项目用 Adam，学习率 `0.001`。PyTorch 默认 `betas=(0.9, 0.999)`、`eps=1e-8`。同一个 `w = 1`、梯度 −12、学习率 0.01 时，Adam 的第一步把 `w` 改成 1.01：方向仍是让损失变小，步长按这个参数自己的梯度历史来。论文里的 Adam 写的是 `β2 = 0.98`、`ε = 1e-9`。这个项目没有传入这两项。逐步的数写在 [pytorch.md](pytorch.md)。

<a id="batch"></a>

## 一批、一轮、训练和测试

一批是若干样本拼在一起，算一个平均损失，然后改一次参数。64 张图的特征形状是 `(64, 784)`，分数形状是 `(64, 10)`，64 张共用同一套 `W`、`b`。

一轮是训练集的每个样本都被看过一遍。60000 张、一批 64 张，一轮有 938 次更新：937 批是 64 张，最后一批是 32 张。每一轮开始时，训练集会把顺序重新打乱，参数接着上一轮的结果，不重新随机。

训练集上的更新用来改参数。测试集的 10000 张只做前向和损失，不调用更新。这样看到的是没参与改参数的图。种子为 0、训练 1 轮时，测试读对 94.510%。

<a id="pytorch"></a>

## PyTorch 把这些概念装到哪里

上面每一格都是数或一步计算。PyTorch 的平台概念，就是这些格的容器和调用顺序。

**张量。** 特征、分数、损失、`W`、`b`、梯度，在库里都是张量。形状说清每一根轴多长，下标按轴的顺序取一格。`dtype` 是整块格子的类型：特征用 `float32`，标签用 `int64`。`device` 是这块数放在哪；这个项目在 `cpu`。轴和下标的细读在 [pytorch-tensor.md](pytorch-tensor.md)。

**计算记录。** 前向里每一次乘法都可以记住自己的输入。`loss.backward()` 顺着这条记录从损失走回每个参数，把梯度填进 `.grad`。`torch.no_grad()` 里面的乘法不留这条记录。测试不改参数，所以 `evaluate` 整段包在这里面。

**Module 和参数登记。** `DigitClassifier` 是一个 `nn.Module`。`__init__` 里写 `self.hidden = nn.Linear(...)`，这一层的 `weight` 和 `bias` 就登记进模型。`model.parameters()` 能把要改的张量全部交出去。输入图片也是张量，它没有登记进 `parameters()`，更新不会改它。

**损失对象。** `nn.CrossEntropyLoss` 是一个可调用对象。它收分数和整数标签，内部做 Softmax，返回一个 0 轴张量，也就是那个损失数。`loss.item()` 把这个数抄成 Python 的小数，方便累加。

**梯度会留在参数上。** 再 `backward` 一次，新梯度加到旧梯度上。一个例子里，梯度 −12 再反传一次变成 −24。每一批开头的 `optimizer.zero_grad()` 把上一批留下的梯度清掉，让这一批单独决定这一步。

**优化器。** `Adam` 拿着 `model.parameters()` 和学习率。`step()` 才改 `W` 和 `b`。Adam 另外为每个参数记两份滑动平均，所以它的记忆不等于参数本身。换一个优化器，前向和损失可以不变，变的是这一步怎么用梯度。

**数据三件套。** `Dataset` 按编号取出一个样本，MNIST 返回一张图和一个整数。`ToTensor` 在取出时把亮度从 0～255 收到 0～1，排成 `(1, 28, 28)`。`DataLoader` 把多个样本叠成一批，训练时打乱顺序，测试时不打乱。

**模式和存盘。** `model.train()` 和 `model.eval()` 切换 `training` 这个开关。这个两层网络没有 Dropout，两种模式下前向算式相同。`state_dict()` 是参数名到张量的字典，`torch.save` 把它写成 `digit.pt`。读一张新图时，先按同样结构新建模型，再 `load_state_dict` 把学到的数抄回去。

## `train.py` 按这个框架走一遍

| 代码 | 框架里的哪一格 |
| --- | --- |
| `torch.manual_seed(0)` | 新建参数时的随机起点固定下来 |
| `datasets.MNIST` + `ToTensor` | 样本：特征是亮度，标签是 0～9 |
| `DataLoader(..., batch_size=64)` | 一批 |
| `DigitClassifier` | 参数和前向：784 → ReLU 隐藏层 → 10 个分数 |
| `CrossEntropyLoss` | 百分比和损失 |
| `Adam(model.parameters(), lr=1e-3)` | 更新规则，要改的就是登记过的参数 |
| `optimizer.zero_grad()` | 清掉上一批的梯度 |
| `scores = model(images)` | 前向 |
| `loss = loss_fn(scores, labels)` | 这一批的平均损失 |
| `loss.backward()` | 填梯度 |
| `optimizer.step()` | 更新 |
| `for epoch` | 一轮，里面把训练集走完 |
| `evaluate` | 测试：前向和损失，不更新 |
| `torch.save(model.state_dict(), ...)` | 把学到的参数存下来 |

<a id="later"></a>

## 这份网络还没有用到的平台零件

上面的框架覆盖 `train.py` 里实际出现的对象。PyTorch 里还有同一套流程的其他零件，这个两层网络没有调用它们：

| 零件 | 它在框架里的位置 |
| --- | --- |
| 卷积层 | 另一种前向。隐藏格看的是一小块像素，而不是 784 个亮度一次加权 |
| Dropout、BatchNorm | 仍是前向里的一层。它们会读 `train()` / `eval()`，两种模式的算式不同 |
| 学习率随步数变化 | 仍是更新。论文里的学习率先升后降；这里每一步都是 `0.001` |
| 显卡 | 仍是张量的 `device`。模型和这一批要在同一块设备上才能相乘 |
| 多机、自动混合精度 | 仍是同一条前向、损失、梯度、更新，只是张量分开放、或用更省的小数类型 |

先能把总表里每一格指到 `train.py` 的一行，并算出小明的分数、百分比、损失和底分梯度。这些后续零件是在这条流程上换某一格的做法。
