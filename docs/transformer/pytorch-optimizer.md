# 优化器：按梯度改参数

`backward` 填好每个参数的梯度之后，优化器负责真正改数。它拿着 `model.parameters()` 里的全部 `W`、`b`，以及一个学习率。`step()` 对每一个格子做一次更新。

```python
optimizer = optim.SGD(model.parameters(), lr=0.01)
optimizer = optim.Adam(model.parameters(), lr=0.001)
```

两行的差别是更新规则和学习率。`model.parameters()` 是同一份名单：`SimpleNN` 里就是 `fc1.weight`、`fc1.bias`、`fc2.weight`、`fc2.bias`。

对照脚本是 [optimizers.py](../../examples/pytorch/lesson2/optimizers.py)。

<a id="example"></a>

## 这个示例里只有一个参数

`OneWeight` 的前向是 `分数 = 3w`，损失是 `(分数 − 5)²`。`w` 从 1 出发。SGD 和 Adam 各用这个公式走一步，所以两边的分数、损失、梯度相同，不同的是 `step()` 怎么改 `w`。

这里没有输入，也没有 `Linear`。`forward` 不接收 `x`，只做 `return 3 * self.w`。3 是写死的系数，训练不改它。要改的只有参数 `w`。`w = 1` 时，分数是 `3×1 = 3`。

`(score - 5) ** 2` 是一个数的平方差，目标就是 5：希望分数靠近 5。现在分数是 3，差是 −2，平方是 4，所以损失是 4。SGD 把 `w` 改成 1.12 之后，分数变成 `3×1.12 = 3.36`，比 3 更靠近 5，还没有到 5。一步的学习率只有 0.01，挪动有限。

```python
self.w = nn.Parameter(torch.tensor([1.0]))
```

`torch.tensor([1.0])` 是形状 `(1,)` 的张量，里面的数是 1。`nn.Parameter` 把它标成模块的可训练参数：`requires_grad` 为 `True`，并且出现在 `model.parameters()` 里。直接把普通张量赋给 `self.t`，那份张量不进入这份名单，优化器也不会改它。

```python
optimizer = optimizer_cls(model.parameters(), lr=0.01)
```

`optimizer_cls` 是类本身，第一次调用时是 `SGD`，第二次是 `Adam`。括号里两份材料：`model.parameters()` 是要改的张量，这里只有 `w`；`lr=0.01` 是学习率。优化器记下这些张量，`step()` 改的就是它们。

`zero_grad()` 清掉参数上已经记下的梯度。这一版 PyTorch 默认把 `.grad` 设成空，而不是留下一张 0。不清的话，下一次 `backward` 会把新梯度加到旧的上面：第一次是 −12，再反传一次变成 −24。清掉之后再反传一次，又是 −12。

`loss.backward()` 从损失沿着前向的记录往回走，把变化率填进 `w.grad`。这一步改的是梯度，`w` 仍是 1。把 1 改成 1.12 或 1.01 的是后面的 `optimizer.step()`。这一例的记录是两步：

```text
分数 = 3 × w = 3
损失 = (3 − 5)² = 4
损失对分数的变化率 = 2×(3 − 5) = −4
分数对 w 的变化率 = 3
w 的梯度 = −4 × 3 = −12
```

分数对 `w` 的变化率是 3，因为分数的定义就是 `3 × w`。`w` 增加 0.001，分数从 3 变成 3.003。

```text
(3.003 − 3) / 0.001 = 3
```

商正好是 3，换成别的步子也是 3。这个 3 就是 `return 3 * self.w` 里写死的乘数。`w` 现在是 1 还是 10，这一步的变化率都是 3。

损失对分数的变化率来自平方。差距 = 分数 − 5，现在是 −2，损失是 4。只把分数增加 0.001，变成 3.001，差距变成 −1.999。

```text
新损失 = (−1.999)² = 3.996001
变化率 = (3.996001 − 4) / 0.001 = −3.999
```

−3.999 已经靠近 −4。设当前差距是 `a`，分数再增加 `h`，平方展开是：

```text
(a + h)² − a² = 2ah + h²
除以 h         = 2a + h
```

`a = 3 − 5 = −2`，所以 `2a = −4`。`h` 很小时，剩下的 `h` 可以忽略，变化率就是 −4。公式里的 2 是平方展开带出来的，括号里的 `(3 − 5)` 是当前差距。

这就是变化率。把 `w` 从 1 改成 1.0001，分数从 3 变成 3.0003，损失从 4 变成 3.99880009。

```text
变化率 = (3.99880009 − 4) / 0.0001 = −11.9991
```

步子再小，这个商就更靠近 −12。`backward` 不用真的去改 `w` 试一遍，它把上面两步的变化率乘起来，直接得到 −12。

这个变化率就是导数。把损失写成 `w` 的函数：

```text
f(w) = (3w − 5)² = 9w² − 30w + 25
f'(w) = 18w − 30
f'(1) = 18 − 30 = −12
```

`f(1) = 4` 是损失本身。`f'(1) = −12` 是损失对 `w` 的导数，也就是 `w.grad`。两步变化率乘起来就是这条导数：`2×(3w − 5)×3 = 18w − 30`。`w = 1` 时，`3w − 5 = −2`，所以 `2×(−2)×3 = −12`。

## 在训练里的位置

```python
optimizer.zero_grad()   # 清掉上一批留在 .grad 里的数
y_pred = model(x)       # 前向
loss = criterion(y_pred, y)
loss.backward()         # 按损失填每个参数的梯度
optimizer.step()        # 用 .grad 改参数本身
```

优化器不计算输出，也不计算损失。梯度已经写在 `weight.grad` 里。`step()` 读这些梯度，改 `weight` 里的数。

调用发生在构造之后。`SGD(model.parameters(), lr=0.01)` 或 `Adam(...)` 已经记下两样东西：要改的参数名单，这里只有 `w`；学习率 `0.01`。`step()` 按这张名单逐个参数做一次更新。这个例子里 `w.grad` 已是 −12，`w` 仍是 1。

`step()` 不把梯度清掉。跑完之后 `w.grad` 还是 −12。下一批要先 `zero_grad()`，再重新 `forward` 和 `backward`，才会得到新的梯度。`step()` 用的永远是调用它那一刻已经写在 `.grad` 里的数。

<a id="sgd"></a>

## SGD

这个例子没有传 `momentum`，默认是 0，也没有权重衰减。`step()` 对 `w` 只做一次减法，写回同一个张量：

```text
w ← w − 学习率 × w.grad
w ← 1 − 0.01 × (−12) = 1.12
```

脚本打出的改之后是 1.12。梯度是负的，减去一个负数，参数变大，挪动距离是 `0.01×12 = 0.12`。分数从 3 变成 `3×1.12 = 3.36`，靠近目标 5。网络里每一个权重格子都按自己的 `.grad` 做这一次减法。

最后写入都是同一个减法：`w ← w − 学习率 × 方向`。上面没传别的参数，方向就是 `w.grad`。本仓库里的 `optim.SGD(..., lr=0.01)` 都是这种调用。

`weight_decay` 或 `momentum` 不为 0 时，`step()` 先改方向，再做这个减法。仍用 `w = 1`、梯度 −12、学习率 0.01，并且每一步都把梯度重新设成 −12：

```text
weight_decay=0.1
方向 = −12 + 0.1×1 = −11.9
w ← 1 − 0.01×(−11.9) = 1.119

momentum=0.9，第一步
方向仍是 −12，w 仍是 1.12，同时记下速度 −12

momentum=0.9，第二步
速度 ← 0.9×(−12) + (−12) = −22.8
w ← 1.12 − 0.01×(−22.8) = 1.348
```

`weight_decay=0.1` 时 float32 打出来是 1.11899996。`momentum=0.9` 的第二步 float32 是 1.34800005。`nesterov=True` 且 `momentum=0.9` 时，第一步的方向变成梯度再加上动量乘速度，同一组数第一步是 1.228。

## Adam

Adam 的 `step()` 也读 `w.grad`，朝梯度的反方向改 `w`。它另外在 `optimizer.state[w]` 里记下这个参数自己的两份历史：梯度的滑动平均 `m`，梯度平方的滑动平均 `v`。PyTorch 默认 `betas=(0.9, 0.999)`、`eps=1e-8`。第一次调用时这两份历史都是 0，步数记成 1。同一个 `w = 1`、梯度 −12、学习率 0.01：

```text
m ← 0.9×0 + 0.1×(−12) = −1.2
v ← 0.999×0 + 0.001×(−12)² = 0.144
m̂ = −1.2 / (1 − 0.9¹) = −12
v̂ = 0.144 / (1 − 0.999¹) = 144
w ← 1 − 0.01 × (−12) / (√144 + 1e-8) = 1.01
```

`m̂`、`v̂` 把第一步里被 0.9 和 0.999 缩小的部分补回来。补完之后 `√v̂ = 12`，和 `m̂` 的绝对值相同，所以这一步的挪动就是学习率 0.01。脚本打出的 `w` 是 1.01。PyTorch 用 float32 存这个数，内部是 1.00999999，`state` 里的 `m` 是 −1.2，`v` 是 0.144。SGD 同一步按原始梯度的大小挪到 1.12。

第二次调用 `step()` 时，`m` 和 `v` 从 −1.2 和 0.144 接着累积，每个参数的步长因此不同。这两份历史留在优化器里，不写进 `w.grad`。

上面为了和 SGD 对照，Adam 的学习率也用了 0.01。常见写法里 Adam 用 `lr=0.001`，SGD 用 `lr=0.01`。学习率改成 0.001 时，第一步的挪动按比例变成 0.001，`w` 变成 1.001。

读数字项目用的是 Adam，学习率 `0.001`，没有另传 `betas`。论文里的 Adam 写的是 `β2 = 0.98`、`ε = 1e-9`。
