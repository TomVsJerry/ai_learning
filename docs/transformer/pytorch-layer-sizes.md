# 一个小网络里的层宽度和批量

网上这段代码先写下四个数：

```python
n_in, n_h, n_out, batch_size = 10, 5, 1, 10
```

它们决定两件事。`n_in`、`n_h`、`n_out` 决定**一个样本**进出每一层时有几个数，因此也决定 `W` 和 `b` 的形状。`batch_size` 决定**这一次把几个样本叠在一张表里**。权重不随批量变大变小。

这里两个 `10` 碰巧相等。前面的 `10` 是 `n_in`，每个样本 10 个特征。后面的 `10` 是 `batch_size`，这一批有 10 个样本。把 `batch_size` 改成 4，输入变成 `(4, 10)`，`Linear(10, 5)` 不用改。

可运行的对照是 [shapes.py](../../examples/pytorch/lesson2/shapes.py)。种子固定为 0 时，打印的形状和下面相同。

<a id="sizes"></a>

## 四个数各管哪根轴

| 名字 | 值 | 它在说什么 | 改它时谁跟着变 |
| --- | --- | --- | --- |
| `n_in` | 10 | 一个样本有 10 个特征。像甜、冰、茶扩成 10 项 | 第一层 `W` 的输入宽度 |
| `n_h` | 5 | 隐藏层给出 5 个检测。像清爽、甜腻扩成 5 格 | 第一层输出宽度，第二层输入宽度 |
| `n_out` | 1 | 每个样本最后留下 1 个数 | 第二层输出宽度，目标 `y` 的最后一轴 |
| `batch_size` | 10 | 这一张表里有 10 行样本 | 只改变数据的第 0 轴 |

一张表的形状是 `(批量, 这一层的宽度)`。前向从头走到尾，批量这根轴一直是 10，变的是后面那根轴的宽度：

```text
x                         (10, 10)   10 个样本，每个 10 个特征
Linear(n_in, n_h)         (10,  5)   每个样本收成 5 个检测
ReLU                      (10,  5)   负数改成 0，形状不变
Linear(n_h, n_out)        (10,  1)   每个样本收成 1 个分数
Sigmoid                   (10,  1)   每个分数收进 0 和 1 之间
y                         (10,  1)   10 个目标，每个是 0.0 或 1.0
```

`x = torch.randn(batch_size, n_in)` 就是按这个形状抽随机数。每一格来自均值 0、方差 1 的正态分布。这 10 行是编出来的虚拟样本，每次运行、只要不固定种子，抽到的数都不同。`y` 是手写的 10 个答案，6 个 `1.0`、4 个 `0.0`，形状必须是 `(10, 1)`，才能和预测值一格对一格。

<a id="weights"></a>

## 宽度怎样写进权重

笔记里的乘法是 `y = x W + b`。PyTorch 把 `W` 存成 `(输出宽度, 输入宽度)`。

| 参数 | 形状 | 格子数 | 对应的宽度 |
| --- | --- | --- | --- |
| 第一层 `weight` | `(5, 10)` | 50 | `n_h` × `n_in` |
| 第一层 `bias` | `(5,)` | 5 | `n_h` |
| 第二层 `weight` | `(1, 5)` | 5 | `n_out` × `n_h` |
| 第二层 `bias` | `(1,)` | 1 | `n_out` |

一共 `50 + 5 + 5 + 1 = 61` 个参数。批量是 10 还是 4，这 61 个数都是同一套：10 行一起乘同一份 `W`。

和读数字网络比，只是宽度不同。那边是 `784 → 128 → 10`，这里是 `10 → 5 → 1`。

<a id="linear-call"></a>

## `Linear()` 这一句在做什么

`nn.Linear(3, 2)` 创建一层。括号里的两个数是宽度：进来 3 个数，出去 2 个数。创建的同时，这一层自带两份参数：

```text
weight  形状 (2, 3)    每一行是一条混合规则
bias    形状 (2,)      每个输出自己的底分
```

之后把这一层当函数来调用。`layer(x)` 对表里的每一行做同一件事：用这一行的特征做加权和，再加底分。笔记里的写法是 `y = x W + b`。PyTorch 存的 `weight` 是 `W` 的转置，所以实际乘法是

```text
y = x @ weight.T + bias
```

用已经算过的清爽、甜腻把 `weight` 填上。`weight` 的第 0 行是清爽的系数 `0, 1, 0.5`，第 1 行是甜腻的系数 `1, 0, 0`，底分是 `[1, 0]`。小明 `[8, 2, 6]` 和热浓茶 `[0, −6, 2]` 叠成 `(2, 3)` 送进去：

```text
清爽 = 0×甜 + 1×冰 + 0.5×茶 + 1
甜腻 = 1×甜 + 0×冰 + 0×茶   + 0

小明    清爽 6    甜腻 8
热浓茶  清爽 −4   甜腻 0
```

出来的形状是 `(2, 2)`。两行共用这一份 `weight` 和 `bias`。空杯 `[0, 0, 0]` 出来是 `[1, 0]`，也就是底分本身。

网上那段代码里的两句，是同一层用了两次，宽度不同：

```python
nn.Linear(n_in, n_h)    # Linear(10, 5)：10 个特征收成 5 个检测
nn.Linear(n_h, n_out)   # Linear(5, 1)：5 个检测收成 1 个分数
```

`Linear(10, 5)` 里有 5 条规则。第 0 条规则是 10 个权重加 1 个底分，得到第 0 个检测；第 1 条规则是另外 10 个权重和另外 1 个底分，得到第 1 个检测。5 条都这样，所以 `weight` 是 `(5, 10)`，`bias` 长度是 5。10 个样本各走一遍这 5 条规则，输出 `(10, 5)`。

新建时这些权重是随机数。训练里的 `step()` 改的就是它们。ReLU 和 Sigmoid 是 `Sequential` 里的下一层，不写在 `Linear` 里面。线性层交出去的数可以是负数；下一次 ReLU 才把负数改成 0。

对照脚本是 [linear_call.py](../../examples/pytorch/lesson2/linear_call.py)。它会打出小明的 `[6.0, 8.0]` 和热浓茶的 `[-4.0, 0.0]`。

<a id="sigmoid"></a>

## Sigmoid 和这一份损失

第二层先得到 1 个分数，Sigmoid 再把它收进 0 和 1 之间：

```text
Sigmoid(分数) = 1 / (1 + e^(−分数))
```

分数是 0 时，结果是 0.5。分数越大，结果越靠近 1。分数越小，结果越靠近 0。

`y` 里的目标已经是 0 或 1。`MSELoss` 对每一个样本算 `(预测 − 目标)²`，再对这 10 个平方取平均。预测若都在 0.5 附近，每个平方大约是 `0.5² = 0.25`，平均损失就在 0.25 左右。

读数字项目的最后一层给出 10 个分数，损失用交叉熵，在内部做 Softmax。这一份网上的例子最后只有 1 个数，损失用平方差，百分比由 Sigmoid 直接算出来。两条流水线的前向、损失、清梯度、反传、更新是同一顺序。

<a id="loop"></a>

## 循环里每一步在做什么

`nn.Sequential` 把四层按书写顺序串起来。`model(x)` 就是依次做线性层、ReLU、线性层、Sigmoid。

```python
for epoch in range(50):
    y_pred = model(x)          # 前向，形状 (10, 1)
    loss = criterion(y_pred, y)  # 一个数：10 个平方差的平均
    optimizer.zero_grad()      # 清掉上一步留在参数上的梯度
    loss.backward()            # 按 61 个参数各填一张梯度
    optimizer.step()           # SGD：参数 ← 参数 − 0.01 × 梯度
```

这里的一轮，就是用**同一批 10 行**做一次更新。50 轮是这 10 行被看 50 次。读数字项目里的一轮才是 60000 张图各看一次，中间有 938 个不同的批。

`zero_grad` 写在前向和损失之后、`backward` 之前，这一步是够用的。梯度要在 `backward` 之前被清掉，`step` 用的是刚刚填上的梯度。

种子为 0、学习率 0.01 时，第 0 步损失是 **0.240085**，第 49 步是 **0.235059**。输出层底分的梯度大约是 −0.032，一步只改 `0.01 × 0.032 ≈ 0.00032`，所以损失下降得很慢，50 步之后预测仍集中在 0.45 到 0.64。把学习率改成 0.5，同样 50 步，损失可以降到约 0.06，预测会分开靠近 0 和 1。原代码没有设置种子，每次运行的初始 `x` 和初始 `W` 都不同，打印出的损失不会正好是这两个数。
