# 张量：一块排好轴的数

张量是 PyTorch 里装数字的对象。格子里的数，就是以前笔记里的甜、冰、茶，或者图上的一格亮度。新的部分是**轴**：取一个格子要写几个下标，由轴的个数决定。形状 `shape` 按轴的顺序写出每一轴有多长。格子总数等于各轴长度相乘。

2 个轴的张量，就是 [矩阵笔记](01-matrix-and-dot-product.md) 里的那张表。1 个轴的张量，就是那里的向量。读数字时出现 3 个轴、4 个轴，只是下标变成 3 个、4 个。

下面的数来自 [tensor_tour.py](../../examples/mnist-digits/tensor_tour.py)。在 `examples/mnist-digits` 里执行 `python tensor_tour.py`，打印结果和这里相同。

<a id="axes"></a>

## 轴和下标

一个数也是张量。甜度 `8.0` 的形状是 `()`，轴的个数是 0，格子数是 1。它没有下标，因为只有这一格。

小明这一杯排成一排，形状 `(3,)`，轴的个数是 1，格子数是 3。这一轴的位置事先说好：0 是甜，1 是冰，2 是茶。

```text
下标   0    1    2
      甜    冰    茶
小明   8    2    6
```

`person[0]` 是 8，`person[1]` 是 2，`person[2]` 是 6。一个下标就能取出一格。

<a id="table"></a>

## 两杯是一张表

把小明和热浓茶叠成两行。形状 `(2, 3)`：轴 0 的长度是 2，选哪一杯；轴 1 的长度是 3，选哪一项原料。格子数是 `2×3 = 6`。

```text
轴 1 →     0 甜    1 冰    2 茶
轴 0
0 小明        8       2       6
1 热浓茶      0      −6       2
```

下标按轴的顺序写，逗号分开：

| 写法 | 读法 | 数 |
| --- | --- | --- |
| `table[0, 1]` | 第 0 杯、第 1 项原料 | 小明的冰 = 2 |
| `table[1, 0]` | 第 1 杯、第 0 项原料 | 热浓茶的甜 = 0 |
| `table[1, 2]` | 第 1 杯、第 2 项原料 | 热浓茶的茶 = 2 |

只写第一个下标，得到整行。`table[0]` 的形状从 `(2, 3)` 去掉轴 0，剩下 `(3,)`，数值是 `[8, 2, 6]`。

冒号表示这一轴全要。`table[:, 1]` 是每一杯的第 1 项，形状 `(2,)`，数值是 `[2, -6]`：小明的冰和热浓茶的冰。

## 同样三个数，可以有不同的轴

`8, 2, 6` 这三格，可以这样摆：

| 写法 | 形状 | 轴在表示什么 |
| --- | --- | --- |
| `[8, 2, 6]` | `(3,)` | 只有原料这一轴 |
| `[[8, 2, 6]]` | `(1, 3)` | 外面那一轴长度是 1，表示「这一批里只有 1 杯」；里面那一轴仍是甜、冰、茶 |
| `[[8], [2], [6]]` | `(3, 1)` | 外面那一轴长度是 3，里面那一轴长度是 1 |

上次写成 `[[8, 2, 6]]`，形状是 `(1, 3)`。两层括号就是两个轴。里面那层是甜、冰、茶；外面那层是「第几杯」，这里只有一杯，所以长度是 1。

线性层把**最后一轴**当成原料。第一层的规则仍是清爽 `= 0×甜 + 1×冰 + 0.5×茶 + 1`，甜腻 `= 1×甜`。三种摆法送进去：

| 送进去的形状 | 出来的形状 | 数值 |
| --- | --- | --- |
| `(3,)` | `(2,)` | `[6, 8]` |
| `(1, 3)` | `(1, 2)` | `[[6, 8]]` |
| `(2, 3)` 两杯 | `(2, 2)` | `[[6, 8], [-4, 0]]` |

`(3,)` 和 `(1, 3)` 算出来的清爽、甜腻都是 6 和 8。差别在外面还留着「第几杯」这个轴。`train.py` 里一批 64 张图拉直后是 `(64, 784)`，最后一轴的 784 是这一张图的亮度，前面的 64 是第几张。出来的分数是 `(64, 10)`：每一行仍是一张图，10 是十个数字的分数。

热浓茶那一行可以手算：清爽 `= 0×0 + 1×(−6) + 0.5×2 + 1 = −4`，甜腻 `= 0`。所以第二行是 `[-4, 0]`。

<a id="add"></a>

## 一排数加到每一行

第一层在矩阵乘完之后还要加 `b1 = [1, 0]`。两杯乘完权重、还没加底分时是：

```text
小明    5    8
热浓茶 −5    0
```

形状 `(2, 2)`。`b1` 的形状是 `(2,)`，只有最后一轴。它加到每一行的对应格上：

```text
小明    5+1=6    8+0=8
热浓茶 −5+1=−4   0+0=0
```

结果形状仍是 `(2, 2)`。这就是小明的 `[6, 8]`，以及热浓茶 ReLU 之前的 `[-4, 0]`。读数字时，`b1` 的长度是 128，会加到每一张图的 128 个检测上。

<a id="order"></a>

## 拉直时的顺序

张量在内存里按行放：先走完一行，再走下一行。两杯这 6 个数的顺序是：

```text
8, 2, 6, 0, −6, 2
```

`view` 按这个顺序重新切段，格子里的数和先后都不改。`table.view(3, 2)` 每 2 个切成一行：

```text
8   2
6   0
−6  2
```

`t()` 是转置，把原来的列变成新的行。形状也变成 `(3, 2)`，数的摆法是：

```text
8   0
2  −6
6   2
```

两种结果的形状都是 `(3, 2)`。`view(3, 2)` 得到的第一行是 `[8, 2]`，`t()` 得到的第一行是 `[8, 0]`。读图时用的是 `view`：按行把亮度接成一长条。

一张 2 行 3 列、中间一列是 8 的小图，形状 `(1, 2, 3)`。三个轴依次是通道、行、列。这里只有 1 个通道。

```text
通道 0：  0   8   0
          0   8   0
```

`picture[0, 0, 1]` 是第 0 通道、第 0 行、第 1 列，等于 8。`picture[0, 1, 1]` 是下一行的同一列，也是 8。`view(1, -1)` 按行拉直，`-1` 让 PyTorch 用格子总数把这一维除出来：`1×2×3 = 6`，所以得到

```text
[[0, 8, 0, 0, 8, 0]]
```

形状 `(1, 6)`。手写数字是同一件事，只是行和列都是 28：`(1, 28, 28)` 拉成 `(1, 784)`。

<a id="batch"></a>

## 一批图再加一个轴

两张小图叠起来，最前面多一个轴，表示第几张。第一张是上面那一笔，第二张全是 0。形状 `(2, 1, 2, 3)`，格子数 `2×1×2×3 = 12`。四个下标的顺序是：第几张、通道、行、列。

| 写法 | 读法 | 数 |
| --- | --- | --- |
| `batch[0, 0, 0, 1]` | 第 0 张、通道 0、行 0、列 1 | 8 |
| `batch[1, 0, 0, 1]` | 第 1 张的同一格 | 0 |

`view(2, -1)` 保持「第几张」这个轴，把后面三个轴收成一排。每张 6 个数，形状 `(2, 6)`：

```text
第 0 张   0  8  0  0  8  0
第 1 张   0  0  0  0  0  0
```

`train.py` 里一批的形状是 `(64, 1, 28, 28)`。四个轴仍是：第几张、通道、行、列。格子数是 `64×1×28×28 = 50176`。`images.view(64, -1)` 得到 `(64, 784)`，每一行是一张图的 784 个亮度。

## 类型和存放位置

`dtype` 是整块数共用的一种格子。小明这排用 `torch.float32`，每个格子是小数。标签 `tensor([0])` 用 `torch.int64`，每个格子是整数，形状 `(1,)`。交叉熵要的标签就是这种整数。

`device` 是这整块数放在哪。这个项目打印出来是 `cpu`。形状、下标和格子里的数，不因为放在 CPU 上而改变。

## 过关自测

1. `table[1, 2]` 是哪一杯的哪一项？数值是多少？
2. `[8, 2, 6]` 和 `[[8, 2, 6]]` 的格子数都是 3。形状分别是什么？送进同一个 `Linear(3, 2)` 后，出来的形状分别是什么？
3. 两杯按行拉直后的 6 个数，顺序是什么？`view(3, 2)` 的第一行，和 `t()` 的第一行，各是哪两个数？
4. 形状 `(64, 1, 28, 28)` 的四个轴各表示什么？`view(64, -1)` 之后的形状是什么？
