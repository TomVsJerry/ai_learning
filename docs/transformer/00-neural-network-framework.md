# 人工神经网络的一条最小框架

用同一套零件判断一杯饮料会不会被喜欢。数字是为了手算选定的，不是训练出来的结果。训练要做的事是改这些数字。

回到 [规划表](README.md)。线性层、ReLU、Softmax 的细节分别在 [03](03-linear-relu-embedding.md) 和 [02](02-softmax.md)。

<a id="frame"></a>

## 从头到尾的顺序

```text
输入向量 x
    ↓
线性层    y = x W1 + b1
    ↓
ReLU      负数改成 0
    ↓
线性层    分数 = y W2 + b2
    ↓
Softmax   分数变成加总为 1 的百分比
    ↓
损失      正确那一类的百分比越接近 1，损失越小
    ↓
训练      改 W1、b1、W2、b2，让损失变小
```

要学的是四组参数：`W1`、`b1`、`W2`、`b2`。换一杯饮料时，这四组不变，变的是输入 `x`。

<a id="task"></a>

## 这个例子在判断什么

输入是甜、冰、茶三格。输出是两个百分比：喜欢、不喜欢。两者都大于 0，加起来是 1。

真实答案用两格表示。喜欢是 `[1, 0]`，不喜欢是 `[0, 1]`。只有一格是 1，表示答案落在那一类。

<a id="params"></a>

## 参数事先写在哪里

第一层把甜、冰、茶收成清爽和甜腻。规则和前面的笔记相同：

```text
清爽 = 0×甜 + 1×冰 + 0.5×茶 + 1
甜腻 = 1×甜 + 0×冰 + 0×茶   + 0
```

这里的 `0, 1, 0.5` 和 `1, 0, 0` 是 `W1`，最后的 `+1` 和 `+0` 是 `b1`。

第二层把清爽、甜腻收成两个分数。这组权重是另外写下的，不是从清爽、甜腻的结果里算出来的：

```text
喜欢   = 0.4×清爽 + 0.1×甜腻 + 0
不喜欢 = −0.2×清爽 + 0×甜腻 + 0.5
```

`0.4, 0.1` 和 `−0.2, 0` 是 `W2`，`0` 和 `0.5` 是 `b2`。不喜欢自带 0.5，是这一层的底分：清爽和甜腻都是 0 时，不喜欢的分数仍是 0.5。

<a id="forward-like"></a>

## 小明这杯：喜欢

输入 `x = [8, 2, 6]`。

第一层：

```text
清爽 = 0×8 + 1×2 + 0.5×6 + 1 = 6
甜腻 = 1×8 + 0×2 + 0×6   + 0 = 8
```

6 和 8 都大于 0，ReLU 之后仍是 `[6, 8]`。这两格被送到第二层。

第二层：

```text
喜欢   = 0.4×6 + 0.1×8 + 0   = 3.2
不喜欢 = −0.2×6 + 0×8 + 0.5 = −0.7
```

Softmax 把分数变成百分比。`e^3.2 ≈ 24.53`，`e^(−0.7) ≈ 0.50`，总和约 25.03：

```text
喜欢   24.53 / 25.03 ≈ 0.980
不喜欢  0.50 / 25.03 ≈ 0.020
```

真实答案是喜欢。损失只看正确那一类的百分比：

```text
损失 = −ln(0.980) ≈ 0.020
```

0.980 接近 1，损失接近 0。模型把大部分百分比给了正确的一类。

<a id="forward-dislike"></a>

## 热浓茶：同一套参数再走一遍

输入 `x = [0, −6, 2]`。`W1`、`b1`、`W2`、`b2` 都不换。

```text
清爽 = 0×0 + 1×(−6) + 0.5×2 + 1 = −4
甜腻 = 0
```

清爽是 −4。ReLU 把这一格改成 0，送到第二层的是 `[0, 0]`。第二层没有清爽和甜腻可用，只剩下底分：

```text
喜欢   = 0
不喜欢 = 0.5
```

百分比约为喜欢 0.378、不喜欢 0.622。真实答案若是不喜欢，损失是 `−ln(0.622) ≈ 0.474`。正确一类拿到的百分比比小明那杯低，损失就更大。

<a id="train"></a>

## 训练在改什么

一次前向把输入算到损失，用的是当前这组 `W` 和 `b`。训练反复做两件事：用现有参数算出损失，再按损失把 `W1`、`b1`、`W2`、`b2` 改一点。改的方向是让正确那一类的百分比变大。

上面的权重是写死来演示流水线的。真的训练之后，清爽怎么从冰和茶里混合、喜欢给清爽多大权重，都会变成另一组数。网络的形状不变：仍然是两层线性层，中间一次 ReLU，最后一次 Softmax。

<a id="why-hidden"></a>

## 为什么要先换成中间的几格

「清爽」「甜腻」是为了读算式起的名字。网络里这两格只是两排新的数。训练不会收到这两个中文名，它只改 `W1` 里的权重。人看完权重，才可能说其中一格比较像清爽。

一层线性层是一次加权和。喜欢的分数永远是 `a×甜 + b×冰 + c×茶 + 底分`。甜每增加 1，喜欢的分数就增加固定的 `a`，和这杯是不是已经很冰无关。这种规则可以用一层直接从甜、冰、茶算到喜欢，中间不必再分一站。

有的喜好不是这种直线。下面四杯只看甜和冰，喜欢的规则是「有甜或者有冰，但不要又甜又冰」：

| 甜 | 冰 | 答案 |
| --- | --- | --- |
| 0 | 2 | 喜欢 |
| 2 | 0 | 喜欢 |
| 0 | 0 | 不喜欢 |
| 2 | 2 | 不喜欢 |

若喜欢的分数是 `a×甜 + b×冰 + 底分`，前两杯要比后两杯高。`(0, 2)` 比 `(0, 0)` 高，要求 `b` 为正。`(2, 0)` 比 `(0, 0)` 高，要求 `a` 为正。那么 `(2, 2)` 会把两份正的贡献加在一起，分数比前两杯更高，会被判成更喜欢。一次加权和做不到「单独出现就加分，一起出现不加分」。

中间先做两个检测，再用 ReLU 只送出正的数量：

```text
偏冰 = ReLU(−1×甜 + 1×冰)
偏甜 = ReLU( 1×甜 + −1×冰)
喜欢 = 偏冰 + 偏甜
```

| 甜 | 冰 | 偏冰 | 偏甜 | 喜欢 |
| --- | --- | --- | --- | --- |
| 0 | 2 | 2 | 0 | 2 |
| 2 | 0 | 0 | 2 | 2 |
| 0 | 0 | 0 | 0 | 0 |
| 2 | 2 | 0 | 0 | 0 |

第一层负责「哪种搭配出现了」，第二层把出现了的检测加起来。`(2, 2)` 两个检测都是 0，喜欢就是 0。这个转弯来自中间的 ReLU：负数不送出，所以两种味道同时很高时，没有一份正的检测可加。

理论上，一层线性层对应一次加权和，分界是平的。中间加一层、并配上 ReLU 这种非线性之后，网络可以先做出多个检测，再组合它们。隐藏格足够多时，这种「检测再组合」能逼近很多从输入到输出的连续关系。格数和层数要多少，取决于规则弯得有多厉害，不是固定要分成清爽和甜腻这两格。

## 一个真实案例：读手写数字

银行支票和邮政编码上的手写数字，用的就是这种网络。一张数字图被划成 28×28 个格子，每格一个亮度，一共 784 个数。输出是 10 个百分比，分别对应 0 到 9，加起来是 1。百分比最高的那一个就是读出的数字。

以一张写着「3」的图为例：

```text
784 个亮度
    ↓
若干层：从亮度里做出笔画、弯钩这类检测
    ↓
10 个分数：像 0 的分数、像 1 的分数……像 9 的分数
    ↓
Softmax
    ↓
例如「3」是 0.91，「8」是 0.06，其余更小
```

中间那些检测没有人事先写成「左弯」「右弯」。训练用大量已经标好「这张图是 3」的图，去改各层的权重。训完以后，前面的层常常对一小段边缘有反应，后面的层才对整字的形状有反应。人可以事后把这些格叫成笔画，名字是看出来的，不是预先写进网络的。

垃圾邮件是同一条流水线的另一个真实用法。输入是一封信里某些词出现了没有。中间层可以表示「免费和发票一起出现」这种搭配。输出两个百分比：是垃圾邮件、不是。单独出现「免费」和同时出现「免费 + 发票」，可以走不同的检测，这就是上一节「单独加分、一起出现另算」的那种转弯。

上面的奶茶网络是这条流水线的缩小版：3 个输入、2 个百分比。读数字是 784 个输入、10 个百分比。零件的顺序相同。

## 过关自测

1. 换一杯饮料时，哪一组数保持不变？
2. 热浓茶的清爽算出 −4。第二层的「喜欢」为什么是 0？
3. 小明的损失约 0.020，热浓茶约 0.474。哪一杯的正确百分比更高？

答案：

1. `W1`、`b1`、`W2`、`b2`。变的是输入 `x`。
2. ReLU 把 −4 改成 0，甜腻也是 0。喜欢的底分是 0，所以分数是 0。
3. 小明。正确一类的百分比约 0.980，热浓茶约 0.622。
