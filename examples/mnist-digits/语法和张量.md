# 对着代码看 Python 语法和张量

这份说明对着 `train.py` 和 `model.py` 写。左边打开这两个文件，右边按顺序看。先认 Python 的写法，再认张量在这条训练流水线里每一次长什么样。

训练在做的事可以收成一句：把一批图片收成一批数，用当前的 `W`、`b` 算出 10 个分数，看正确那一格离「百分之百」有多远，再按这个差距改 `W`、`b`。Python 负责把这句话写成计算机能一步步执行的文本。张量负责把「一批数」装在一个对象里，让加法和乘法一次作用在全部数上。

## 2. Python 语法：这份代码里实际出现的写法

### 2.1 注释和文档字符串

以 `#` 开头的一行是注释。Python 读到 `#`，这一行后面的字全部跳过。

```55:56:train.py
        # 清掉上一批留在参数上的梯度，避免加到这一批上。
        optimizer.zero_grad()
```

真正执行的只有 `optimizer.zero_grad()`。上面那行中文是写给读代码的人的。

文件最开头、函数 `def` 下面，用三个引号包起来的文字叫文档字符串：

```32:38:train.py
def make_loaders(batch_size: int):
    """准备训练图和测试图。

    ToTensor 把 0～255 的亮度除以 255，收成 0～1。
    标签是 0～9 的整数，不是 10 格里放一个 1。
    交叉熵损失接受的就是这种整数：它表示正确百分比落在第几格。
    """
```

它也是一段字符串，程序默认不会把它打印出来。放在函数开头，是这个函数的说明书。`train.py` 第 1 行到第 16 行同理，是整个文件的说明书。

### 2.2 `import`：使用已经写好的工具

```18:25:train.py
import argparse
from pathlib import Path

import torch
from torch import nn
from torch.utils.data import DataLoader
from torchvision import datasets, transforms

from model import DigitClassifier
```

Python 一个文件就是一个模块。`import argparse` 的意思是：去加载标准库里名叫 `argparse` 的模块，之后用 `argparse.ArgumentParser` 这样的写法使用它。点号左边是模块，右边是模块里的名字。

`from pathlib import Path` 只把模块里的 `Path` 这一个名字拿进来。后面就可以直接写 `Path(...)`，不用写 `pathlib.Path(...)`。

`from torch import nn` 把 PyTorch 里的 `nn` 拿进来。`nn` 是 neural network 的缩写，里面放着层和损失函数，例如 `nn.Linear`、`nn.CrossEntropyLoss`。

`from model import DigitClassifier` 里的 `model` 不是别人装的库，就是同一目录下的 `model.py`。把 `.py` 去掉，就是模块名。

同一行可以拿多个名字：`from torchvision import datasets, transforms`。

### 2.3 名字和赋值

```29:29:train.py
DATA_DIR = Path(__file__).resolve().parent / "data"
```

`=` 是赋值：算出右边，贴上左边这个名字。之后写 `DATA_DIR`，就是在用右边那个文件夹路径。

全大写 `DATA_DIR` 是一种习惯：这个名字在整个文件里当常数用，读代码的人一眼知道它不会在训练循环里被改掉。Python 本身不禁止你改它，大写只是约定。

这一行从左往右拆开：

- `__file__` 是 Python 自动准备的字符串，内容是当前这个文件自己的路径，也就是 `train.py` 的路径。两边的双下划线表示「Python 自己定义的特殊名字」。
- `Path(...)` 把字符串变成一个路径对象，后面才能用 `/` 拼接文件夹。
- `.resolve()` 把相对路径变成绝对路径。
- `.parent` 是这个文件所在的文件夹，也就是 `mnist-digits`。
- `/ "data"` 接上子文件夹 `data`。对路径对象，`/` 表示「进入下一级」，结果是 `mnist-digits/data`。

所以训练数据放在脚本旁边的 `data` 里，不依赖你在哪个目录敲的运行命令。

再看普通赋值：

```50:52:train.py
    total_loss = 0.0
    correct = 0
    seen = 0
```

`0` 是整数，`0.0` 是小数。这里先把三个计数器放在 0，循环里再往上加。`total_loss` 用小数，是因为损失本来就是 `0.3438` 这种带小数点的数。

`+=` 是「加上右边，再存回左边」：

```69:69:train.py

```

它和写成 `total_loss = total_loss + loss.item() * labels.size(0)` 是同一件事。

### 2.4 函数：把一段步骤起个名字

```47:48:train.py
def train_one_epoch(model, loader, loss_fn, optimizer):
    """用现有参数走完一整遍训练图，并按损失改参数。"""
```

`def` 定义函数。函数是一段起了名字的步骤。定义的时候不执行函数体，只是把步骤记下来。真正执行发生在有人调用它的时候：

```130:130:train.py
        train_loss, train_acc = train_one_epoch(model, train_loader, loss_fn, optimizer)
```

调用时，括号里按顺序送进四个对象。函数内部把它们叫作 `model`、`loader`、`loss_fn`、`optimizer`。外面的变量名叫 `train_loader`，进去之后改叫 `loader`。两边是同一个对象，只是门口换了一块名牌。

函数里的缩进（行首的空格）表示「这些行属于这个函数」。Python 用缩进划分代码块，同一层步骤必须左右对齐。`train_one_epoch` 里面的 `for` 再缩进一层，`for` 里面的 `optimizer.zero_grad()` 又缩进一层。读的时候跟着缩进往里走，就是「进入这一段」。

`return` 把结果交回调用的地方，函数到这里结束：

```74:74:train.py
    return total_loss / seen, correct / seen
```

逗号隔开的两个值会打包成一个元组。调用处写成 `train_loss, train_acc = ...`，是把这个元组再拆开：第一个数给 `train_loss`，第二个数给 `train_acc`。这里第一个是平均损失，第二个是读对的比例。

### 2.5 参数的两种传法

看这一行：

```40:40:train.py

```

括号里有两种参数：

- `DATA_DIR` 按位置传。它是第一个参数，对应「数据放哪」。
- `train=True`、`download=True`、`transform=to_tensor` 按名字传，叫关键字参数。名字写在调用处，位置就可以不背。

`True` 和 `False` 是 Python 里的两个布尔值，表示「是」和「否」。`train=True` 表示要那 6 万张训练图。下一行 `train=False` 表示要另外 1 万张测试图。

函数定义时也可以给参数一个默认值。`model.py` 里：

```16:16:model.py
    def __init__(self, hidden_size: int = 128):
```

`hidden_size: int = 128` 的意思是：调用时如果没写这个参数，就用 128。`DigitClassifier()` 和 `DigitClassifier(128)` 造出来的网络一样。`train.py` 里写的是 `DigitClassifier(args.hidden_size)`，把命令行传来的数送进去。

冒号后面的 `int` 是类型标注，告诉读代码的人：`batch_size` 应当是整数。它不改变运行。你就算传入一个别的东西，Python 也不会因为这个冒号就拦住你。它的作用是让人和编辑器知道每个名字装的是什么。

### 2.7 `for` 循环

```54:54:train.py
    for images, labels in loader:
```

`for` 表示「对右边的每一个元素，执行缩进的那一段」。`loader` 是 `DataLoader`。它每次交出一批：64 张图和 64 个标签，包在一个元组里。

`images, labels` 是拆包。一次交出的东西有两项，左边就写两个名字。`images` 接到图，`labels` 接到标签。6 万张、每批 64 张，这个循环大约转 938 次（最后一批可能不足 64 张）。

轮数的循环用 `range`：

```129:129:train.py
    for epoch in range(1, args.epochs + 1):
```

`range(1, 3)` 产生 `1, 2`。右边那个数本身不包含在内，所以要写 `args.epochs + 1`。`--epochs 2` 时，`epoch` 先是 1，再是 2。每一轮都会把 6 万张再走一遍。

`enumerate` 在打印百分比时出现：

```108:108:train.py
    for digit, probability in enumerate(probabilities.tolist()):
```

`enumerate` 一边给出序号，一边给出元素。10 个百分比走下来，`digit` 是 0 到 9，`probability` 是对应的那个小数。序号正好就是数字类别，所以可以直接当「像几」来打印。

### 2.8 点号：向对象要数据，或让对象做一件事

点号有两种用法，这份代码里都有。

向对象要它带着的数据：

```69:69:train.py
        total_loss += loss.item() * labels.size(0)
```

`labels.size(0)` 是在问这张量：第 0 维有多长。第 0 维是批量，所以结果是这一批有几张图，平时是 64。

让对象做一件事，括号不能省：

```56:56:train.py
        optimizer.zero_grad()
```

`zero_grad` 是优化器的一个函数，挂在对象上时叫方法。括号表示「现在就做」。没有括号的 `optimizer.zero_grad` 只是把这个方法本身拿在手里，步骤还没发生。

有的方法要参数。`scores.argmax(dim=1)` 里的 `dim=1` 告诉它：沿着哪一维去找最大。这个 `dim` 在第 3.8 节对着形状讲。

### 2.9 比较会得到真假，真假可以拿来计数

```71:71:train.py
        correct += (predicted == labels).sum().item()
```

`predicted` 和 `labels` 都是 64 个数。`==` 逐个比较，得到 64 个真或假。读对的位置是真。`.sum()` 把真当成 1、假当成 0 加起来，就是这一批读对了几张。

比较的两边必须能对齐。64 个预测对 64 个标签，每个位置各比一次。这是张量的比较，和 Python 里 `3 == 3` 得到一个 `True` 是同一类运算符，作用的对象从「一个数」变成了「一排数」。

### 2.10 f-string：把数嵌进句子

引号前面的 `f` 表示：花括号里的名字先换成它的值，再拼成一句字符串。`truth` 是 7、`predicted` 是 7 时，打印出来就是「第一张测试图的真实数字是 7，读成 7」。

花括号里还可以规定小数的样子：

### 2.11 切片：从一批里取出一部分


方括号是取出其中一段。`images` 的第 0 维是批量。`images[:1]` 表示这一维从开头取到第 1 个位置、不包含第 1 个，所以只留下第 0 张图。

### 2.13 装饰器 `@`

```77:78:train.py

```

`@` 写在 `def` 上面，叫装饰器。它把下面这个函数包了一层。`@torch.no_grad()` 的效果是：执行 `evaluate` 的整段时间里，张量运算不记录梯度。测试只是看读得怎样，不需要回头改 `W`、`b`。不记录，就省下内存，也不会在测试图上积累梯度。

### 2.15 类：`model.py` 里的网络是一张图纸

```15:21:model.py
class DigitClassifier(nn.Module):
    def __init__(self, hidden_size: int = 128):
        super().__init__()
        self.hidden = nn.Linear(28 * 28, hidden_size)
        self.output = nn.Linear(hidden_size, 10)
```

`class` 定义一类对象的图纸。`DigitClassifier(nn.Module)` 表示这张图纸建立在 `nn.Module` 已有的能力上：登记子模块、收集参数、调用时自动进入 `forward`。括号里的 `nn.Module` 叫父类。

图纸本身不是网络。`train.py` 第 122 行的 `model = DigitClassifier(args.hidden_size)` 才按照图纸做出一个网络对象。每次调用 `DigitClassifier(...)` 都会得到一个新的对象，各自带自己的 `W` 和 `b`。

`__init__` 是造对象时自动执行的函数，用来把这个对象一开始要有的东西放好。这里放了两层 `nn.Linear`。

`self` 就是「正在被制造的那个对象」。`self.hidden = ...` 把第一层装到这个对象身上，之后在别的方法里用 `self.hidden` 拿回来。没有 `self`，这个名字出了 `__init__` 就不存在了。

`super().__init__()` 先让父类 `nn.Module` 完成它自己的初始化。父类要先准备好「登记子模块」的本子，后面的 `self.hidden = ...` 才能被登记进去。登记之后，`model.parameters()` 才找得到这两层的 `W` 和 `b`。

`forward` 是前向计算。训练里写的是 `scores = model(images)`，没有直接写 `model.forward(images)`。`nn.Module` 规定：对对象使用括号，就会去调用 `forward`。中间它还可以做一些记账。日常写代码时记住「`model(images)` 就是在做前向」就够了。

## 3. 张量

### 3.1 张量是什么

一个 Python 数，例如 `correct = 0`，名字下面只挂着一个整数。

一张图有 `28×28 = 784` 个亮度。如果用 784 个互不相干的 Python 变量去装，乘权重时要写 784 次乘法。张量把这 784 个数装进一个对象，再标好它们排成几行几列。一次乘法作用在整个对象上，每个位置按自己的下标参加运算。

可以把它想成有形状的一张数表：

- 0 维：一个数。损失 `loss` 就是这样，一个小数，但仍然包在张量里。
- 1 维：一排数。一个标签批次是 64 个整数，排成一排。
- 2 维：一张表。拉直后的一批图是 64 行、每行 784 列。一层的权重 `W1` 也是一张表。
- 3 维：一张图。1 个通道、28 行、28 列。
- 4 维：一批图。64 张叠在一起，每一张仍是 `1×28×28`。

维度就是「有几层下标」。张量里的每一个数都是普通小数或整数，张量额外记住这些数的形状，以及运算时要不要记录梯度。

这份代码里的张量都是 `torch.Tensor`，由 PyTorch 创建和计算。打印一个张量时，通常会看到里面的数、形状 `size`、数据类型 `dtype`，以及是在 CPU 上还是在显卡上。这个项目没把计算搬到显卡，张量在 CPU 上。

数据类型也要分开看：

- 图片亮度和分数是小数，类型一般是 `float32`，32 位浮点数。
- 标签是 0～9 的整数，类型是 64 位整数。交叉熵要的就是这种整数：它表示正确的那一格是第几格。

### 3.2 形状怎么读

形状写成一串长度，从左到右是第 0 维、第 1 维、第 2 维……

`(64, 1, 28, 28)` 读作：

| 位置 | 长度 | 含义 |
| --- | --- | --- |
| 第 0 维 | 64 | 这一批有 64 张图 |
| 第 1 维 | 1 | 每张图 1 个颜色通道，灰度 |
| 第 2 维 | 28 | 28 行 |
| 第 3 维 | 28 | 28 列 |

`labels.size(0)` 就是在读第 0 维的长度。`size` 和 `shape` 说的是同一份信息。`images.size(0)` 同样是这批有多少张。

最后一个不满的批次可能是 `(32, 1, 28, 28)` 这种。后面的三维持不变，变的是批量那一维。网络的权重和批量无关：同一套 `W`、`b` 作用在这一维的每一张上。

### 3.3 一次前向，形状怎么变

下面按 `train_one_epoch` 里的一批，批量取 64，隐藏层取 128。

```text
images      (64, 1, 28, 28)     64 张图，每张 1×28×28，亮度已经在 0～1
labels      (64,)               64 个整数，每个是 0～9
flat        (64, 784)           每张图拉成一行
detected    (64, 128)           每张图 128 个检测，负数已被 ReLU 变成 0
scores      (64, 10)            每张图 10 个分数，对应数字 0 到 9
loss        ()                  一个数，这一批的平均损失
predicted   (64,)               64 个整数，每张图分数最大的那一格
```

`()` 表示 0 维，里面只有一个数。它仍是张量。后面要用 `.item()` 才能变成 Python 小数，原因在第 3.10 节。

权重不随着这一批出现和消失，它们住在 `model` 里面：

```text
hidden.weight    (128, 784)     笔记里的 W1，PyTorch 按 (输出, 输入) 来存
hidden.bias      (128,)         b1
output.weight    (10, 128)      笔记里的 W2
output.bias      (10,)          b2
```

笔记里的乘法是 `y = x W`，所以 `W1` 按 784×128 来想。PyTorch 存成 `(128, 784)`，计算时先转置再乘，每个亮度乘出来的结果和笔记相同。`b` 会加到每一行上：64 张图共用同一个 `b1`。

### 3.4 第一张张量从哪来

原始文件 `data/MNIST/raw` 里是字节，不是张量。`datasets.MNIST` 负责把字节读成图和标签。`transforms.ToTensor()` 在每次取出一张图时做转换，得到张量。

它做两件事：

1. 像素从 0～255 的整数除以 255，变成 0～1 的小数。黑是 0，白笔画接近 1。
2. 排列从「行、列」改成「通道、行、列」。一张灰度图的形状是 `(1, 28, 28)`。

转换发生在「取出一张」的时候。`DataLoader` 再把 64 次取出的结果在第 0 维拼起来，才有 `(64, 1, 28, 28)` 和 `(64,)`。

拼的规则是：图和图叠在新的批量维上，标签和标签接成一排。这就是 `for images, labels in loader` 里两个名字各自的来历。

`shuffle=True` 只改变每一轮取图的顺序，不改变张量的形状，也不改变某一张图和它的标签的对应关系。打乱的是「哪 64 张碰上了」，每张图仍然带着自己的标签。

### 3.5 `view`：换一种形状看同一批数

```30:30:model.py
        flat = images.view(images.size(0), -1)
```

`view` 不改数的先后顺序，只改下标的切法。`images.size(0)` 是批量，保持不动。`-1` 表示「这一维多长，请用总数除以前面各维算出来」。

一张图有 `1×28×28 = 784` 个数，所以 `-1` 算出来是 784。`(64, 1, 28, 28)` 变成 `(64, 784)`。数还是那些数，只是每张图从一块 28×28 看成了一行 784 列。

`nn.Linear` 要的就是这种「一批行」。每一行是一个样本，每一列是一个输入特征。64 行一起乘同一张权重表。

`view` 要求元素总数不变。`64×1×28×28` 和 `64×784` 都是 50176 个数，所以能换。换成 `(64, 100)` 就会报错，因为 6400 不等于 50176。

### 3.6 线性层在张量上做的乘法

`detected = torch.relu(self.hidden(flat))` 这一行里有两步。

`self.hidden(flat)` 对 `flat` 的每一行做 `y = x W1 + b1`。一行 784 个数，乘出 128 个数。64 行各自乘，得到 `(64, 128)`。64 行用的是同一份 `W1` 和 `b1`。

`torch.relu` 作用在这个结果的每一个数上：负数变成 0，正数保持原值。形状仍然是 `(64, 128)`。这种「同一个运算作用在每个元素上」是张量运算的常态。你不写 64×128 次 `if`，张量一次做完。

`self.output(detected)` 再把每一行的 128 个数乘成 10 个分数，形状变成 `(64, 10)`。第 0 列是「像 0」的分数，第 9 列是「像 9」的分数。分数可以是负数，也可以大于 1。它还不是百分比。

### 3.7 `dim`：沿着哪一维做运算

`scores` 的形状是 `(64, 10)`。

```70:70:train.py
        predicted = scores.argmax(dim=1)
```

`dim=1` 表示沿着第 1 维，也就是每张图自己的 10 个分数里找最大。每一行得到 1 个下标，64 行得到 64 个下标，形状从 `(64, 10)` 收成 `(64,)`。下标 7 就是「这张图读成 7」。

如果写成 `dim=0`，就会沿着批量那一维比，变成「这 10 个数字里，64 张图各自谁的分数最大」，形状是 `(10,)`。那是另一个问题。这份代码要的是每张图一个答案，所以是 `dim=1`。

Softmax 用的是同一个 `dim`：

```103:103:train.py
    probabilities = torch.softmax(scores, dim=1)[0]
```

`dim=1` 表示百分比做在每一行内部：一行 10 个数先取指数，再除以这 10 个指数的和，于是这一行加起来是 1。64 行各算各的。百分比最大的位置和分数最大的位置是同一个，因为指数函数保持大小顺序。

末尾的 `[0]` 是切片之后的结果：`show_one_prediction` 只送了 1 张图，`softmax` 出来的形状是 `(1, 10)`，`[0]` 取出那唯一的一行，形状变成 `(10,)`。后面的 `for` 才能一个数字一个百分比地打印。

### 3.8 损失也是张量

```61:61:train.py
        loss = loss_fn(scores, labels)
```

`scores` 是 `(64, 10)` 的小数，`labels` 是 `(64,)` 的整数。交叉熵对每一行：先把 10 个分数变成 10 个百分比，再取标签指向的那一格的负对数。64 个损失再平均，得到一个 0 维张量。

百分比越接近 1，这一项越接近 0。整个 `loss` 越接近 0，这一批就读得越有把握。

这个平均是张量内部算完的。`loss` 打印出来像一个小数，类型却还是张量，因为它还连着前面的 `scores`，再往前连着 `W` 和 `b`。这条连接就是计算图。`loss.backward()` 沿着这条连接往回走，用链式法则算出每个权重的梯度，写到对应参数的 `.grad` 上。

梯度的形状和参数一样。`W1` 是 `(128, 784)`，它的梯度也是 `(128, 784)`。每一个权重都知道：自己变大一点，损失会跟着变大还是变小。

### 3.9 哪些张量带梯度

不是所有张量都要回头改。

- `model` 里的 `weight` 和 `bias` 在创建时就标记为需要梯度。它们是要学习的 `W` 和 `b`。
- `images`、`labels` 是数据，不需要梯度。输入不靠损失去改。
- `scores` 和 `loss` 由带梯度的权重算出来，因此自己也带着那条连接，`backward` 才有路可走。
- `loss.item()` 取出的是一个普通 Python 小数。它和计算图断开了，只适合累加、打印，不能再 `backward`。

`optimizer.zero_grad()` 把上一批写在 `.grad` 上的数清掉。PyTorch 默认把新梯度加到旧梯度上。不清掉，这一批的方向会叠着上一批。

`optimizer.step()` 读取每个参数的梯度和自己记住的历史步长，真正改写 `W` 和 `b` 里面的数。改的是张量里的数值，张量对象还是原来的那个。所以下一张图来的时候，`model.parameters()` 拿到的已经是更新后的权重。

`@torch.no_grad()` 下面算出来的 `scores` 不再保留连接。测试集上的损失可以用来打印，它的 `backward` 没有记录可用。`evaluate` 里也就没有 `backward` 和 `step`。

### 3.10 从张量回到 Python 的数

训练循环里要做 Python 的累加和打印，就要把「一个数的张量」取出成 Python 自己的整数或小数。

| 写法 | 得到什么 | 用在哪 |
| --- | --- | --- |
| `loss.item()` | 一个 Python 小数 | 累加整轮的损失 |
| `(predicted == labels).sum().item()` | 一个 Python 整数 | 累加读对的张数 |
| `int(probabilities.argmax())` | 一个 Python 整数 | 把「读成几」放进句子 |
| `probabilities.tolist()` | 一个 Python 列表，里面 10 个小数 | 交给 `for` 逐个打印 |
| `labels[0]` 再 `int(...)` | 一个 Python 整数 | 真实标签 |

`.item()` 只能用在只含一个数的张量上。`loss` 是 0 维，可以。`scores` 有 640 个数，直接 `.item()` 会报错。要先用 `argmax`、`sum` 这类运算收成一个数。

累加时乘上 `labels.size(0)`，是因为 `loss` 已经是这一批的平均。最后一批也许只有 32 张，它的平均不能和 64 张的平均同等相加。先乘回张数，最后再除以 `seen`（整轮看过的总张数），得到的才是「每一张的平均损失」。

`return total_loss / seen, correct / seen` 交回去的两个结果已经是 Python 小数，不再是张量。所以 `main` 里可以直接放进 f-string。

### 3.11 保存下来的是张量里的数

```140:141:train.py
    weights_path = Path(__file__).resolve().parent / "digit.pt"
    torch.save(model.state_dict(), weights_path)
```

`state_dict()` 是一个字典。字典是「名字 → 值」的一张表。这里的名字类似 `hidden.weight`、`hidden.bias`、`output.weight`、`output.bias`，值就是那四个张量。`torch.save` 把这四块数写进 `digit.pt`。

它不保存 Python 类的源码，也不保存训练循环。`predict.py` 要先执行 `DigitClassifier()`，按同一张图纸造出形状相同的空张量，再把文件里的数填回去。`--hidden-size` 一旦和训练时不一样，`W1` 的行数对不上，加载会失败。

## 4. 把训练的一批连起来读

下面是 `train_one_epoch` 里一批数据走过的路径。缩进仍然表示「这些步骤属于这一批」。

```54:71:train.py
    for images, labels in loader:
        optimizer.zero_grad()
        scores = model(images)
        loss = loss_fn(scores, labels)
        loss.backward()
        optimizer.step()

        total_loss += loss.item() * labels.size(0)
        predicted = scores.argmax(dim=1)
        correct += (predicted == labels).sum().item()
        seen += labels.size(0)
```

按名字对照：

1. `images`、`labels` 从加载器拆包出来。一个是 4 维浮点张量，一个是 1 维整数张量。
2. `zero_grad()` 清掉参数上的旧梯度。参数是模型里的张量。
3. `model(images)` 进入 `forward`：`view` 把图拉成 `(64, 784)`，两层线性层得到 `(64, 10)` 的分数。
4. `loss_fn(...)` 把分数和整数标签合成一个 0 维张量 `loss`。
5. `backward()` 把梯度写到每个 `W`、`b` 上。
6. `step()` 按梯度改这些张量里的数。
7. 剩下三行不再改网络。它们把张量收成 Python 的数，累加到 `total_loss`、`correct`、`seen`，供这一轮结束时计算平均损失和读对比例。

一整轮把这个循环走完。`--epochs 2` 把整轮再做一遍。第二遍的 `W`、`b` 已经是第一遍改过的数。测试循环的结构相同，少了清梯度、反向和 `step`，所以测试图只贡献打印出来的损失和读对比例。
